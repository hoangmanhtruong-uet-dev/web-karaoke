# Failure response matrix

All JSON API errors use `{ success:false, error:{ code, message } }`, omit stack/SQL/host/Prisma metadata, set `Cache-Control: no-store`, and carry `X-Request-ID` when produced through the shared helper. `Alert` means aggregate/rate-based alert, not one alert per request.

| Scenario                                      | HTTP / public code                                                        | Public message                    | Retry / Retry-After                                                  | Log / alert                                               | Request ID                      | Rollback                                     |
| --------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------- | ------------------------------- | -------------------------------------------- |
| Invalid JSON                                  | 400 `INVALID_JSON`                                                        | Request body is not valid JSON    | no / no                                                              | none / no                                                 | yes                             | before TX                                    |
| Invalid origin                                | 403 `INVALID_ORIGIN`                                                      | generic invalid origin            | no / no                                                              | sampled security metric / threshold                       | yes                             | before TX                                    |
| Unauthorized                                  | 401 `UNAUTHORIZED`                                                        | Authentication required           | after login / no                                                     | audit failed login only / threshold                       | shared helper where used        | before TX                                    |
| Forbidden                                     | 403 `FORBIDDEN`                                                           | No permission                     | no / no                                                              | security audit / threshold                                | yes                             | before TX                                    |
| Validation failure                            | 422 `VALIDATION_ERROR`                                                    | Invalid request details           | after correction / no                                                | none / no                                                 | yes                             | before TX                                    |
| Payload too large                             | 413 `PAYLOAD_TOO_LARGE`                                                   | Body invalid or too large         | no / no                                                              | aggregate metric / threshold                              | yes                             | before TX                                    |
| Unsupported media type                        | 415 `UNSUPPORTED_MEDIA_TYPE`                                              | Body invalid or too large         | after correction / no                                                | none                                                      | yes                             | before TX                                    |
| Rate limited                                  | 429 `RATE_LIMITED`                                                        | Too many requests                 | yes / decision seconds                                               | no per-request error; threshold transition audit          | not yet on limiter response: P2 | before business logic                        |
| Database unavailable/reset/TLS/DNS            | 503 `DEPENDENCY_UNAVAILABLE`                                              | Service temporarily unavailable   | yes / 5s                                                             | structured redacted error / page on sustained rate        | yes                             | database guarantees atomic rollback          |
| Database pool exhausted                       | 503 `DEPENDENCY_UNAVAILABLE`                                              | Service temporarily unavailable   | yes / 5s                                                             | structured code `P2024` / alert                           | yes                             | no TX or rolled back                         |
| External email unavailable                    | request already committed; outbox retries; job reports controlled failure | no public booking/contact failure | automatic backoff / scheduled time                                   | delivery/outbox summary / dead-letter alert               | event ID                        | booking/contact TX remains committed         |
| Request/query timeout                         | 503 dependency timeout or 500 unexpected                                  | generic                           | safe GET may retry; POST only with same idempotency key / 5s for 503 | structured / latency+timeout alert                        | yes                             | TX timeout rolls back                        |
| Server overloaded                             | target 503 `SERVER_OVERLOADED`                                            | Temporarily unavailable           | yes / 5s                                                             | aggregate metric / alert                                  | target yes                      | reject before TX; **admission shedder OPEN** |
| Duplicate booking/room conflict               | 409 `ROOM_UNAVAILABLE` or `BOOKING_CONFLICT`                              | slot unavailable                  | user may choose another slot / no                                    | business metric / unusual spike                           | yes                             | TX rollback                                  |
| Idempotency key reused with different payload | 409 `IDEMPOTENCY_KEY_REUSED`                                              | key used for different request    | no; generate key only for changed payload                            | audit metric / abuse threshold                            | yes                             | no duplicate write                           |
| Unexpected internal error                     | 500 `INTERNAL_ERROR` or route-specific generic code                       | Request could not complete        | not automatic for POST / no                                          | structured redacted error / alert                         | yes on shared mapper            | TX rollback                                  |
| Maintenance mode                              | target 503 `MAINTENANCE`                                                  | Temporarily unavailable           | yes / operator value                                                 | one state-change event / alert routing suppressed by plan | target yes                      | reject before TX; **implementation OPEN**    |

Known gap: several admin handlers still rely on Next.js uncaught-error handling and do not use the centralized mapper. This remains a P1 checklist item rather than being represented as complete.
